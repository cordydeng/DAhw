# Project 2：EOL 設計規則檢查器報告

## 一、題目需求與規則解讀

本專題依據 `Project_2_v1_EOL_DRC.docx`，以 C++ 與 Boost.Geometry 實作線端（End-of-Line，EOL）設計規則檢查器。程式讀取沿用 Project 1 格式的布局資料，辨識 M1 金屬的 EOL 邊，檢查附近是否有其他同層金屬侵入指定範圍，並輸出違規位置與 SVG 圖形。

題目中的參數如下，單位皆為 μm：

| 參數 | 數值 | 意義 |
| --- | --- | --- |
| `eolWidth` | 0.6 | 判定 EOL 邊的最大長度，包含等於此值的情況 |
| `eolSpace` | 1.0 | EOL 邊向外正前方所需保留的間距 |
| `eolWithin` | 0.4 | 圖 2(a) 中，檢查範圍超出 EOL 邊兩端的擴張距離 |
| `parallelLength` | 0.7 | 第一張示意圖中，parallel halo 從 EOL 邊沿金屬往後延伸的長度 |
| `parallelHalo` | 0.4 | 第一張示意圖中，parallel halo 與金屬側邊的距離 |

題目第一張圖要求 object 3 必須留在 parallel halo 之外；圖 2(a) 則描繪 EOL 邊前方及前方兩側的違規區域。依老師的補充說明，parallel halo（以及向前、側向的延伸範圍）定義的是「可能發生違規的區域」：區域內沒有其他金屬代表規則通過，並不代表規則未啟用或被略過。因此本實作對每一條 EOL 邊都檢查以下三塊區域，任一區域被其他金屬侵入即為違規：

1. 前方 spacing 區域（圖 2(a)）：沿金屬外側向前延伸 1.0 μm，並沿 EOL 邊的方向從兩端各擴張 0.4 μm。若 EOL 邊長為 0.6 μm，則總寬度為 1.4 μm、深度為 1.0 μm。
2. 兩側 parallel halo（第一張圖）：位於金屬兩側、與側邊相距 0.4 μm 以內，並從 EOL 邊沿金屬往後延伸 0.7 μm，左右各一塊。

## 二、資料結構與輸入處理

程式以 Boost.Geometry 的 `Point`、`Polygon`、`MultiPolygon` 與 `Box` 表示座標、多邊形、多個多邊形及軸向包圍盒，並使用以下資料結構管理布局與結果：

| 資料結構 | 儲存內容 | 用途 |
| --- | --- | --- |
| `Layer` | 圖層名稱與編號 | 找出 M1 對應的圖層 |
| `Shape` | 圖形編號、圖層、多邊形、包圍盒 | 儲存金屬的實際幾何形狀與顯示範圍 |
| `Layout` | 圖層集合與圖形集合 | 保存解析後的輸入資料 |
| `Violation` | EOL 編號、來源與目標金屬編號、方向、原因、檢查範圍 | 記錄每筆違規 |
| `DrcResult::EolEdge` | EOL 編號及兩端點 | 記錄辨識出的 EOL 邊，供繪圖使用 |
| `DrcResult` | EOL 邊集合與違規集合 | 保存完整檢查結果 |

`parse_layout()` 逐行讀取輸入，以區段狀態區分圖層、矩形與多邊形資料。空白行及以 `#` 開頭的註解會被略過；矩形由兩個對角座標建立，多邊形則由依序排列的頂點建立。所有圖形皆經過 `bg::correct()` 修正頂點順序與閉合狀態，再以 `bg::is_valid()` 檢查幾何合法性。

取得 M1 圖層後，`merge_same_layer_shapes()` 以 `bg::union_()` 合併該層的金屬幾何，接著依合併結果重新編號。因此，輸出中的金屬編號代表合併後的多邊形，不一定對應輸入行的順序。EOL 判定使用合併後的實際邊界，避免將重疊金屬內部的原始矩形邊誤判為線端。

## 三、EOL 偵測與違規檢查演算法

### 3.1 邊界前處理

程式逐一取得合併後多邊形的外環頂點，移除重複的閉合端點，並刪除位於同一直線、沿相同方向延伸的中間頂點。這可避免一條完整邊因輸入或合併產生的分段，被誤判為多條較短的 EOL 邊。

### 3.2 辨識 EOL 邊

對每一條候選邊，依序檢查以下條件：

1. 該邊必須為水平或垂直邊，且長度大於零。
2. 邊長必須小於或等於 `eolWidth = 0.6`。
3. 與該邊兩端相接的邊，必須垂直於候選邊，且皆朝金屬內部延伸。

第三項條件用來區分凸出的金屬線端與凹陷處的短邊。程式依順時針外環的方向計算內、外法向量，再以相鄰邊在內法向量上的投影判定其延伸方向。每條通過條件的邊都取得唯一的 `E#` 編號。

### 3.3 建立檢查範圍

設 `s = eolSpace = 1.0`、`w = eolWithin = 0.4`。各方向 EOL 的檢查矩形如下：

| EOL 方向 | EOL 邊座標 | 檢查範圍 |
| --- | --- | --- |
| 向右 | `x = a`，`y ∈ [b, c]` | `x ∈ [a, a+s]`，`y ∈ [b-w, c+w]` |
| 向左 | `x = a`，`y ∈ [b, c]` | `x ∈ [a-s, a]`，`y ∈ [b-w, c+w]` |
| 向上 | `y = a`，`x ∈ [b, c]` | `x ∈ [b-w, c+w]`，`y ∈ [a, a+s]` |
| 向下 | `y = a`，`x ∈ [b, c]` | `x ∈ [b-w, c+w]`，`y ∈ [a-s, a]` |

這些矩形涵蓋 EOL 正前方及前方兩側。另設 `L = parallelLength = 0.7`、`h = parallelHalo = 0.4`，兩側 parallel halo 的矩形如下：

| EOL 方向 | EOL 邊座標 | 兩側 parallel halo |
| --- | --- | --- |
| 向右 | `x = a`，`y ∈ [b, c]` | `x ∈ [a-L, a]`，`y ∈ [b-h, b]` 及 `y ∈ [c, c+h]` |
| 向左 | `x = a`，`y ∈ [b, c]` | `x ∈ [a, a+L]`，`y ∈ [b-h, b]` 及 `y ∈ [c, c+h]` |
| 向上 | `y = a`，`x ∈ [b, c]` | `x ∈ [b-h, b]` 及 `x ∈ [c, c+h]`，`y ∈ [a-L, a]` |
| 向下 | `y = a`，`x ∈ [b, c]` | `x ∈ [b-h, b]` 及 `x ∈ [c, c+h]`，`y ∈ [a, a+L]` |

parallel halo 向後延伸時可能與來源金屬本身重疊（例如合併後凸出的短線端），因此檢查時一律略過來源金屬。

### 3.4 判斷金屬侵入

對每條 EOL 邊的三塊檢查矩形，程式分別遍歷其他同層、合併後的金屬多邊形，略過來源金屬本身。使用 `bg::intersection()` 計算目標金屬與檢查矩形的交集；只要任一交集多邊形的面積大於 `EPS = 1e-9`，即記錄一筆違規。

目前採用「正面積侵入」的判定方式，只有邊界接觸、沒有面積重疊時不回報。因此，前方距離恰好為 1.0 μm 時可通過（題目要求 spacing 大於或等於 eolSpace）；與金屬側邊恰好相距 0.4 μm，或恰好位於 parallel length 0.7 μm 的盡頭時也不回報。

違規以「檢查區域與目標金屬」為單位記錄，並標明原因為 `EOL spacing < 1.0` 或 `parallel halo intruded (0.4 x 0.7)`。同一檢查區域若侵入多個目標金屬，會產生多筆紀錄；兩條 EOL 邊若彼此違反各自的範圍，也會分別記錄。目前檢查對象為多邊形外環上的 Manhattan 邊界，未對內部孔洞邊界進行 EOL 偵測。

### 3.5 輸出結果

終端機輸出違規總數，以及每筆違規的 EOL 編號、來源與目標金屬編號、方向、原因、檢查矩形座標，以及目標金屬實際侵入檢查矩形的範圍（intruding metal，即侵入部分的包圍盒）。圖形輸出包含合併後金屬圖與 DRC 結果圖；結果圖使用鮮橘色表示發生違規的完整檢查範圍、鮮紅色表示目標金屬實際侵入的部分、深綠色表示 EOL 邊。金屬編號在標示之後繪製，並加上白色描邊以保持可讀性。

若沒有違規，兩張圖仍會產生，且內容完全相同，只顯示金屬及其編號。

## 四、範例執行結果與違規位置

`sample_input.txt` 與題目文件中的 layout 完全相同（6 個 M1 矩形）。輸入矩形 4 與 5 互相重疊，合併後共有 5 個金屬多邊形，編號如下：

| 合併後編號 | 對應輸入矩形 | 範圍 (μm) |
| --- | --- | --- |
| M1 | 第 6 個 | (8.6, 2.2) – (14, 2.8) |
| M2 | 第 3 個 | (2.0, 2.0) – (4.0, 2.6) |
| M3 | 第 2 個 | (0, 1.0) – (6.1, 1.6) |
| M4 | 第 1 個 | (4.0, 0) – (7.8, 0.6) |
| M5 | 第 4、5 個合併 | (7.0, 1.0) – (14, 1.6) 加上 (10.4, 0.8) – (11, 1.8) |

程式共辨識出 12 條 EOL 邊，偵測到 3 筆違規：

| 違規 | EOL 邊 | 被侵入的區域 | 侵入的金屬及範圍 (μm) | 說明 |
| --- | --- | --- | --- | --- |
| V1 (E6) | M3 右端，x = 6.1，y ∈ [1.0, 1.6] | 前方 spacing 區域 (6.1, 0.6) – (7.1, 2.0) | M5，(7.0, 1.0) – (7.1, 1.6) | 兩金屬間距 0.9 < 1.0 |
| V2 (E9) | M5 凸出部分的上端，y = 1.8，x ∈ [10.4, 11.0] | 前方 spacing 區域 (10.0, 1.8) – (11.4, 2.8) | M1，(10.0, 2.2) – (11.4, 2.8) | 間距 0.4 < 1.0 |
| V3 (E12) | M5 左端，x = 7.0，y ∈ [1.0, 1.6] | 前方 spacing 區域 (6.0, 0.6) – (7.0, 2.0) | M3，(6.0, 1.0) – (6.1, 1.6) | 與 V1 為同一處間距，從另一端檢查 |

其餘 EOL 邊皆通過檢查。範例中有多組間距恰好為 0.4 μm 的邊界情況，例如 M4（y 上緣 0.6）與 M3、M5（y 下緣 1.0），以及 M2（y 下緣 2.0）與 M3（y 上緣 1.6）。這些金屬只接觸 parallel halo 或前方側向擴張區域的邊界，沒有面積重疊，因此依「間距大於或等於規定值即合格」判定為通過。M5 凸出部分兩側的 parallel halo 與 M5 本身重疊，但因屬於同一導體而不列入。

除題目範例外，也以自訂測試確認 parallel halo 的行為：金屬侵入 halo 時回報 `parallel halo intruded`；金屬恰好位於 0.7 μm 盡頭、與側邊恰好相距 0.4 μm、或在前方恰好相距 1.0 μm 時皆不回報。

## 五、編譯與執行方式

程式與相關檔案位於專案的 `project2/` 目錄，原始碼為 `project2.cpp`。編譯環境需支援 C++17，並能找到 Boost 標頭檔。

在 `project2/` 目錄執行：

```bash
g++ project2.cpp -std=c++17 -O2 -o project2.exe
./project2.exe sample_input.txt
```

若 macOS 上的 Boost 安裝於 `/opt/homebrew/include`，可明確指定標頭檔路徑：

```bash
clang++ project2.cpp -std=c++17 -O2 -I/opt/homebrew/include -o project2.exe
./project2.exe sample_input.txt
```

程式接受一個輸入檔路徑。以下為矩形輸入範例，所有座標單位皆為 μm：

```text
number_of_layers 1
M1 1
end_of_layer

number_of_rectangles 1
1 4.0 0.0, 7.8 0.6
end_of_rectangle
```

矩形資料的第一個數字為圖層編號，後方為兩個對角座標；若輸入多邊形，則使用 `number_of_polygons` 與 `end_of_polygon` 包住各多邊形的圖層及頂點資料。

每次成功執行後，程式會在執行時的工作目錄產生或覆寫以下檔案：

| 輸出檔案 | 內容 |
| --- | --- |
| `metal_clean.svg` | 合併後的 M1 金屬圖形與編號 |
| `eol_drc.svg` | 有違規時顯示 EOL 邊、違規檢查範圍及實際侵入部分；無違規時與金屬圖相同 |

SVG 可使用瀏覽器或支援 SVG 的編輯器開啟。若未提供正確的命令列參數、輸入檔無法開啟、幾何資料不合法，或輸出檔無法寫入，程式會顯示錯誤訊息並以非零狀態結束。

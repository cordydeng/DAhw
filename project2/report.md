# Project 2：EOL 設計規則檢查器報告

## Project Objective（專題目標）

本專題的目標是以 C++ 與 Boost.Geometry 建立一套自動化的線端（End-of-Line，EOL）間距檢查程式，將布局中的金屬幾何資料轉換為可檢查的邊界與區域，找出各 metal layer 上不符合指定 EOL spacing 條件的位置。透過此實作，將設計規則中的距離與方向條件轉換為具體的幾何運算，並以文字與圖形呈現檢查結果。

具體目標如下：

1. 讀取沿用 Project 1 格式的矩形與多邊形布局資料，保留每個輸入 metal 的獨立形狀與編號，僅針對實際外露的有效線端進行檢查。
2. 依邊長、方向及相鄰邊的幾何關係，自動辨識符合條件的 EOL 邊。
3. 依 `eolWidth = 0.6 μm`、`eolSpace = 1.0 μm` 與 `eolWithin = 0.4 μm`，實作圖 2(a) 所示的 EOL 檢查範圍，偵測其他同層金屬的侵入。
4. 以「EOL 邊與目標金屬」為單位記錄違規，輸出違規總數及對應位置，供使用者核對。
5. 每個 metal layer 各輸出一張純金屬 SVG，另將所有層的 EOL 邊、違規檢查範圍及實際侵入區域合併為一張 DRC 結果圖，直接儲存於執行目錄，並於作圖前清除本程式產生的舊圖。

### EOL 檢查條件

本專題採用下列條件實作 EOL 檢查。判斷分為「辨識線端」與「檢查線端附近是否有其他金屬侵入」兩個階段；找到 EOL 邊之後，仍須滿足侵入條件才構成違規。

1. **檢查對象與邊界：** 檢查圖層名稱為 `M` 加數字的 metal layer（例如 M1、M2、M3）。各輸入 metal 保留原有 shape ID 與幾何形狀；程式另建立同層金屬的聯集，僅用來辨識實際外露的邊界。被其他同層金屬覆蓋的邊及相接後的內部接縫，都不當成 EOL。不同層不互相遮蔽，也不互相構成 EOL violation；所有層沿用相同規則參數。
2. **線端方向與長度：** 實際外露的候選邊必須為非零長度的水平或垂直邊，且完整邊長小於或等於 `eolWidth = 0.6 μm`。共線的中間頂點會先移除；例如兩條相接的 0.4 μm 寬金屬若形成 0.8 μm 寬的同一線端，便不符合條件，不能分開當作兩條 0.4 μm 的 EOL。
3. **線端形狀：** 依聯集外環判斷，與候選邊兩端相接的邊必須都垂直於候選邊，並朝金屬內部延伸。這表示候選邊位於凸出的末端；凹槽底部或部分遮蔽後形成的凹角短邊，即使長度不超過 0.6 μm，也不能直接當作 EOL。
4. **檢查區域：** 將有效的實際 EOL 邊映射回原始 metal 的外環，對各 metal 擁有的外露線段分別編號。沿外法向量向前延伸 `eolSpace = 1.0 μm`，並沿該線段方向從兩端各延伸 `eolWithin = 0.4 μm`，形成矩形。若外露線段長為 `L`，矩形沿邊方向的寬度就是 `L + 0.8 μm`，向前深度為 `1.0 μm`，不延伸至線端後方。EOL 寬度門檻則已先以完整的實際邊界判定。
5. **違規成立條件：** 其他同層的輸入金屬圖形只要與有效外露 EOL 的檢查矩形有正面積重疊，即記錄一筆 violation；只略過來源 shape 自身。金屬重疊本身不算 EOL violation，已被遮蔽的內部邊也不建立檢查區域。目標金屬不需要也有 EOL 邊，只要其幾何形狀侵入有效檢查區域即可。程式以交集面積大於 `EPS = 1e-9` 作為實際判定條件，因此只有邊界相碰、沒有面積侵入時不算違規。
6. **違規計數：** 每個「EOL 邊 × 侵入的目標金屬」組合各計一筆。同一條 EOL 邊若被兩個不同金屬侵入，算兩筆；若 `A→B` 與 `B→A` 各自觸犯 EOL 檢查範圍，也分別計數。

同層 metal 若被另一個單一 metal 完整包含（允許邊界重合），視為同一個對象，只保留外側 metal 的 shape ID，再進行 EOL 判定與繪圖；若兩者幾何完全相同，則保留先讀入的 ID。此規則以 `bg::covered_by()` 判斷實際多邊形的完整覆蓋，來源與目標端都不重複計數。部分重疊或不同層的圖形仍各自保留；多個 metal 聯合覆蓋一個 metal 不屬於這項單一圖形包含去重規則。

例如，若一條向右的 EOL 邊位於 `x = 3.0`、`y ∈ [0.0, 0.6]`，它的檢查矩形為 `x ∈ [3.0, 4.0]`、`y ∈ [-0.4, 1.0]`。其他金屬若侵入此矩形並產生正面積交集，就會違規；若金屬僅在 `x = 4.0` 處接觸矩形邊界、未進入矩形內部，則不回報。因此，檢查時需要同時考慮向前距離與側向範圍，而不只是比較兩個金屬的最近距離。

上述條件對應本程式採用的圖 2(a) 直接檢查方式：每條符合幾何條件的 EOL 邊都啟動檢查。目前未將 `parallel length = 0.7 μm` 作為啟動條件，也未實作內部孔洞邊界的 EOL 偵測；這些是本專題實作的範圍限制。

## 一、EOL 定義、題目需求與規則解讀

EOL（End-of-Line，線端）是金屬線在某個延伸方向上終止時，位於末端的邊界。它是一條邊，而不是單一端點。例如，一條沿水平方向延伸的長方形金屬線，其左、右兩端的垂直短邊就是線端；上、下兩條水平長邊則是沿線延伸的側邊。若金屬線改為垂直延伸，線端便位於上、下兩端。

以長度 3.0 μm、線寬 0.6 μm 的水平金屬矩形為例，左、右線端各是一條長度 0.6 μm 的邊。因此，EOL 邊的長度對應此處的金屬線寬，並不是金屬線沿水平方向的總長度。對較複雜的多邊形，則需依實際邊界辨識各個凸出線段的末端。

在本程式中，接受 EOL 檢查的實際外露邊必須為水平或垂直邊、長度不超過 `eolWidth = 0.6 μm`，而且兩端相接的邊都必須垂直於它並朝金屬內部延伸。最後一項條件用來辨識凸出的線端，排除凹陷處的短邊。程式先確認同層聯集的有效線端，再將外露部分對應回各輸入 metal，詳細實作見第三部分。

EOL 的存在本身不代表違規。EOL spacing 規則要求線端外側的指定範圍保留足夠空間；只有其他金屬侵入該範圍時，才記錄為 spacing violation。因此，程式會先辨識 EOL 邊，再對每條 EOL 邊建立檢查區域並搜尋其他金屬。

本專題依據 `Project_2_v1_EOL_DRC.docx`，以 C++ 與 Boost.Geometry 實作線端（End-of-Line，EOL）設計規則檢查器。程式讀取沿用 Project 1 格式的布局資料，辨識各 metal layer 金屬的 EOL 邊，檢查附近是否有其他同層金屬侵入指定範圍，並輸出違規明細、分層純金屬圖及合併 DRC 圖。

題目中的參數如下，單位皆為 μm：

| 參數 | 數值 | 意義 |
| --- | --- | --- |
| `eolWidth` | 0.6 | 判定 EOL 邊的最大長度，包含等於此值的情況 |
| `eolSpace` | 1.0 | EOL 邊向外正前方所需保留的間距 |
| `eolWithin` | 0.4 | 圖 2(a) 中，檢查範圍超出 EOL 邊兩端的擴張距離 |
| Parallel length | 0.7 | 第一張示意圖中用於判定附近平行邊條件的長度 |

題目第一張圖說明帶有平行邊條件的 EOL 檢查：附近金屬符合指定條件時，才要求 EOL spacing。圖 2(a) 則直接描繪 EOL 邊前方及前方兩側的違規檢查範圍。本實作採用圖 2(a) 的直接檢查方式，每條符合幾何條件的 EOL 邊都進行檢查，不以 parallel halo 作為啟動條件，也不將進入該 halo 本身當成違規。因此，目前不使用 0.7 μm 的 parallel length；此做法可能比帶有平行邊啟動條件的規則回報更多違規，兩者並非完全等價。

目前的 EOL 檢查區域為矩形，沿金屬外側向前延伸 1.0 μm，並沿 EOL 邊的方向從兩端各擴張 0.4 μm。若 EOL 邊長為 0.6 μm，則檢查範圍沿邊方向的總寬度為 1.4 μm，向前深度為 1.0 μm；範圍不延伸至 EOL 後方。

## 二、資料結構與輸入處理

程式以 Boost.Geometry 的 `Point`、`Polygon`、`MultiPolygon` 與 `Box` 表示座標、多邊形、聯集結果及軸向包圍盒，並使用以下資料結構管理布局與結果：

| 資料結構 | 儲存內容 | 用途 |
| --- | --- | --- |
| `Layer` | 圖層名稱與編號 | 找出各 metal layer，供檢查與圖例使用 |
| `Shape` | 圖形編號、圖層、多邊形、包圍盒 | 儲存金屬的實際幾何形狀與顯示範圍 |
| `Layout` | 圖層集合與圖形集合 | 保存解析後的輸入資料 |
| `Violation` | 圖層、EOL 編號、來源與目標金屬編號、方向、原因、檢查範圍 | 記錄每筆違規 |
| `DrcResult::EolEdge` | EOL 編號、兩端點、圖層及來源 shape ID | 記錄辨識出的外露 EOL 線段，供繪圖使用 |
| `DrcResult` | EOL 邊集合與違規集合 | 保存完整檢查結果 |

`parse_layout()` 逐行讀取輸入，以區段狀態區分圖層、矩形與多邊形資料。空白行及以 `#` 開頭的註解會被略過；矩形由兩個對角座標建立，多邊形則由依序排列的頂點建立。所有圖形皆經過 `bg::correct()` 修正頂點順序與閉合狀態，再以 `bg::is_valid()` 檢查幾何合法性。

`metal_layers()` 取得所有名稱為 `M` 加數字的圖層後，`main()` 從 `layout.shapes` 篩選出屬於這些圖層的圖形，存入 `metal_shapes`，保留 `parse_layout()` 配置的全域唯一 shape ID。`exposed_boundaries()` 另以 `bg::union_()` 建立每層的實際外部邊界，供 EOL 幾何判定使用；此暫存聯集不取代原始輸入 metal。輸出編號仍對應輸入幾何的讀取順序，略過非金屬層後可能不連續。

篩選時亦執行同層完整包含去重：先比較圖層與包圍盒，再以 `bg::covered_by(inner.poly, outer.poly)` 判斷內側多邊形是否完全落在外側多邊形之內或邊界上。若目前圖形已被保留的圖形完整覆蓋，便略過；反之，若目前圖形完整包含先前保留的圖形，便移除內側圖形並保留目前的外側圖形。因此大小圖形的讀入順序不影響最後保留的外部形狀，幾何完全相同時則保留第一個 ID。只有包圍盒包含而實際幾何未完整覆蓋時，不會去重。

## 三、EOL 偵測與違規檢查演算法

整體流程由 `main()` 篩選輸入 metal，再呼叫 `check_eol()`。後者利用 `exposed_boundaries()` 與 `find_eol_edges()` 辨識實際線端，經 `owned_edge_parts()` 對應原始 metal 後，建立檢查區域、偵測侵入並彙整結果。主要流程如下：

```text
讀取 layout
  → 取出所有 metal layer 的輸入圖形，保留各自的幾何形狀與 ID
  → 另建立每層金屬的聯集外環，排除內部接縫與被覆蓋的邊
  → 判斷實際外露邊是否符合完整 EOL 寬度與凸出線端條件
  → 將有效 EOL 的外露線段對應回原始 shape：
       建立朝外的 EOL 檢查矩形
       與其他同層 shape 做面積交集測試
       記錄每個偵測到的違規區域
  → 輸出文字與 SVG
```

### 3.1 邊界前處理

`exposed_boundaries()` 先取得同層金屬聯集的外環。`find_eol_edges()` 再移除重複的閉合端點，並刪除位於同一直線、沿相同方向延伸的中間頂點，避免將一條完整的實際邊界誤判為多條短 EOL。這也能排除重疊處與相接處的內部接縫。

對應程式碼為 `find_eol_edges()` 開頭的頂點處理，以及 `remove_collinear_vertices(vertices)`。處理後的 `vertices[i]` 與 `vertices[(i+1) % n]` 才是一條實際要檢查的邊。

### 3.2 辨識 EOL 邊

對每一條候選邊，依序檢查以下條件：

1. 該邊必須為水平或垂直邊，且長度大於零。
2. 邊長必須小於或等於 `eolWidth = 0.6`。
3. 與該邊兩端相接的邊，必須垂直於候選邊，且皆朝金屬內部延伸。

第三項條件用來區分凸出的金屬線端與凹陷處的短邊。程式依順時針外環的方向計算內、外法向量，再以相鄰邊在內法向量上的投影判定其延伸方向。每條通過條件的邊都取得唯一的 `E#` 編號。

程式中的對應判斷如下：

```cpp
const bool vertical = std::abs(dx) <= EPS && std::abs(dy) > EPS;
const bool horizontal = std::abs(dy) <= EPS && std::abs(dx) > EPS;
if (!vertical && !horizontal) continue;
if (edge_length > EOL_WIDTH + EPS) continue;
```

接著以 `ox, oy` 表示外法向量、`ix, iy` 表示內法向量。只有候選邊兩端的相鄰邊都沿內法向量延伸、且沒有沿候選邊方向延伸時，才保留為 EOL；不符合者以 `continue` 略過。

### 3.3 建立檢查範圍

設 `s = eolSpace = 1.0`、`w = eolWithin = 0.4`。各方向 EOL 的檢查矩形如下：

| EOL 方向 | EOL 邊座標 | 檢查範圍 |
| --- | --- | --- |
| 向右 | `x = a`，`y ∈ [b, c]` | `x ∈ [a, a+s]`，`y ∈ [b-w, c+w]` |
| 向左 | `x = a`，`y ∈ [b, c]` | `x ∈ [a-s, a]`，`y ∈ [b-w, c+w]` |
| 向上 | `y = a`，`x ∈ [b, c]` | `x ∈ [b-w, c+w]`，`y ∈ [a, a+s]` |
| 向下 | `y = a`，`x ∈ [b, c]` | `x ∈ [b-w, c+w]`，`y ∈ [a-s, a]` |

這些矩形同時涵蓋 EOL 正前方及前方兩側，無須另外建立沿金屬側邊向後延伸的 halo。

在 `check_eol()` 中，`normalized_box(...)` 將依方向計算出的四個座標正規化為 `Box`；隨後呼叫 `check_region(...)`，將該 `Box` 與其他金屬進行比對。

建立矩形前，`owned_edge_parts(edge, source)` 會比對有效線端與各原始 metal 的外環邊，要求兩者位於同一直線、方向一致，且有正長度的共線重疊。只有對應到的外露部分才會回傳；部分遮蔽的區段不會因此重新成為 EOL。若同一個有效線端由多個輸入 shape 共同構成，會分別保留各 shape 所屬的線段與來源 ID，且線端是否符合 `eolWidth` 已先由完整聯集邊界決定。

### 3.4 判斷金屬侵入

對每條 EOL 邊的檢查矩形，`check_region()` 遍歷其他同層的輸入金屬圖形，略過來源 shape 本身。`shape_overlaps_region()` 使用 `bg::intersection()` 計算目標金屬與檢查矩形的交集；只要任一交集多邊形的面積大於 `EPS = 1e-9`，即記錄偵測結果。

目前採用「正面積侵入」的判定方式，只有邊界接觸、沒有面積重疊時不回報。因此，前方距離恰好為 1.0 μm 時可通過；僅接觸側向擴張邊界時也不回報。這是目前程式對邊界情況的處理方式。

違規以「EOL 邊與目標金屬」為單位記錄。同一檢查區域若侵入多個目標金屬，會產生多筆紀錄；若 `A→B` 與 `B→A` 都被偵測到，兩者代表不同 EOL 邊的檢查結果，因此也會分別計為兩筆 violation。目前檢查對象為多邊形外環上的 Manhattan 邊界，未對內部孔洞邊界進行 EOL 偵測。

### 3.5 輸出結果

終端機以 `drc.violations.size()` 輸出違規總數，並列出每筆違規的 EOL 編號、來源與目標金屬編號、方向、原因及檢查矩形座標。

`write_layer_svgs()` 先呼叫 `refresh_generated_svgs()`，清除目前工作目錄中符合本程式命名的舊 SVG（包含舊版 `metal_clean.svg`、`eol_drc.svg` 及分層結果），不清除其他 SVG、不搜尋子目錄。接著按圖層篩選 metal，逐層呼叫 `write_clean_metal_svg()`，產生 `metal_clean_M1.svg`、`metal_clean_M2.svg` 等純金屬圖，只畫本層的金屬、編號及圖例。最後呼叫一次 `write_drc_svg()`，將所有層的 metal、EOL 與 violation 合併輸出至 `eol_drc.svg`，不建立額外資料夾。若輸入重複使用圖層名稱，純金屬圖的檔名另加 `_L圖層編號` 以避免互相覆寫。

合併的 DRC 圖以不同顏色區分各層金屬與 EOL 邊。鮮橘色表示違規的完整檢查範圍、鮮紅色表示目標金屬實際侵入的部分，滑鼠停留於標示可查看其圖層與 EOL 編號。金屬標籤採用 `M2/S7` 格式，表示 M2 的 shape 7，並加上白色描邊；圖中 violation 數量對應終端機的全部圖層總數。

無論有無違規，皆產生每層純金屬圖及一張合併 DRC 圖；無違規時 DRC 圖顯示 `0 violation(s)`，仍畫出金屬、編號與有效 EOL 邊。清除舊圖的動作在輸入解析及 EOL 檢查成功後、作圖前執行。

## 四、編譯與執行方式

程式與相關檔案位於專案的 `project2/` 目錄，原始碼為 `project2.cpp`。編譯環境需支援 C++17，並能找到 Boost 標頭檔。

在 `project2/` 目錄執行：

```bash
g++ project2.cpp -std=c++17 -O2 -o project2.exe
./project2.exe sample_input.txt
```

若 macOS 上的 Boost 安裝於 `/opt/homebrew/include`，可明確指定標頭檔路徑：

```bash
clang++ project2.cpp -std=c++17 -O2 -I/opt/homebrew/include -o project2.exe
./project2.exe sample_input.txt
```

程式接受一個輸入檔路徑。以下為矩形輸入範例，所有座標單位皆為 μm：

```text
number_of_layers 1
M1 1
end_of_layer

number_of_rectangles 1
1 4.0 0.0, 7.8 0.6
end_of_rectangle
```

矩形資料的第一個數字為圖層編號，後方為兩個對角座標；若輸入多邊形，則使用 `number_of_polygons` 與 `end_of_polygon` 包住各多邊形的圖層及頂點資料。

每次成功執行後，程式會在執行時的工作目錄產生或覆寫以下檔案：

| 輸出檔案 | 內容 |
| --- | --- |
| `metal_clean_M1.svg`、`metal_clean_M2.svg` 等 | 每個 metal layer 各自的純金屬圖，不含 EOL 或違規標示 |
| `eol_drc.svg` | 所有圖層合併的金屬、EOL 邊及違規位置，顯示總違規數 |

SVG 可使用瀏覽器或支援 SVG 的編輯器開啟。若未提供正確的命令列參數、輸入檔無法開啟、幾何資料不合法，或輸出檔無法寫入，程式會顯示錯誤訊息並以非零狀態結束。
